ADGuard VPN Desktop — справка

ADGuard VPN Desktop — сторонняя графическая оболочка для AdGuard VPN CLI в Linux. Это не официальное настольное приложение AdGuard; проект не связан с AdGuard.

Подключение

Показывает состояние AdGuard VPN CLI, позволяет загрузить список локаций, подключиться к выбранному серверу и отключиться. Предупреждение CLI о невозможности настроить системный DNS означает, что DNS-запросы могут обходить VPN.

Приложения

Вкладка предлагает два режима, соответствующие официальной конфигурации AdGuard VPN CLI:

  • Все приложения через AdGuard — устанавливает для CLI режим маршрутизации TUN AUTO. По документации AdGuard этот режим предназначен для системной маршрутизации без индивидуальной настройки приложений.
  • Избранные приложения через AdGuard — устанавливает режим SCRIPT и использует отдельный механизм маршрутизации выбранного процесса. Для SCRIPT нужен исполняемый пользовательский сценарий CLI; его можно создать штатной командой config create-route-script. Существующий сценарий не перезаписывается автоматически.

Переключение требует подтверждения. После изменения режима, если VPN уже подключён, переподключите VPN, чтобы CLI применил новые правила. До этого фактическая маршрутизация не считается подтверждённой.

В режиме избранных доступны поиск, список программ, добавление по полному пути, выбор и снятие флажков. Запуск через VPN разрешён только при подтверждённом режиме SCRIPT и успешных проверках TUN, маршрутов и DNS. Кнопка «Прекратить работу приложения через VPN» снимает правила маршрутизации, не завершая само приложение.

Важно. Ограничения процесса: один защищённый запуск за раз; уже запущенные экземпляры и D-Bus activation не поддерживаются. Реальную маршрутизацию необходимо проверять на конкретной системе.

DNS и защита

Тестовые операции с профилями ограничены специально разрешёнными тестовыми профилями. Отдельные кнопки временного системного DNS действуют на активные Ethernet/Wi-Fi устройства NetworkManager через nmcli device modify. Постоянные connection profiles не редактируются.

Перед применением helper проверяет подключение TUN и маршрут к каждому upstream с UID вошедшего в систему пользователя. Он сохраняет состояние активных устройств, применяет временные IPv4/IPv6 DNS-параметры и повторно проверяет эффективные DNS-серверы. После этого интерфейс проверяет маршруты и выполняет реальные UDP DNS-запросы к upstream.

Для восстановления используется nmcli device reapply только если на интерфейсе всё ещё активно то же соединение NetworkManager; результат сравнивается с сохранёнными исходными DNS-серверами. Если соединение сменилось, а временный override всё ещё виден, состояние восстановления сохраняется и не удаляется.

Системная служба adguard-vpn-desktop-dns-guard наблюдает за состоянием VPN и восстанавливает DNS при отключении VPN, незавершённой транзакции или остановке службы. После перезагрузки она сверяет boot ID и очищает устаревшее состояние. При ошибке восстановления состояние сохраняется для повторной попытки.

Эти проверки повышают надёжность, но не заменяют интеграционный тест реального системного resolver и DNS/IPv6 трафика на Debian 13.

Диагностика и безопасность

  • Длинные сообщения об ошибках можно прокручивать и выделять для копирования.
  • Не публикуйте пароли, токены, приватные ключи и персональные сетевые снимки.
  • Если проверка маршрутов или DNS не пройдена, безопасный запуск приложения должен быть запрещён.
