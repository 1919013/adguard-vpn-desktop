# ADGuard VPN Desktop

Независимая графическая оболочка для **AdGuard VPN CLI** в Linux. Проект не разработан, не одобрен и не поддерживается компанией AdGuard.

> Состояние: ветка разработки проходит проверку. Проверка работы на целевых настольных системах и подготовка пакетов ещё не завершены.

## Реализованные функции в текущей ветке

- Подключение и отключение AdGuard VPN CLI, просмотр и выбор VPN-серверов.
- Вкладка управления AdGuard VPN CLI: обнаружение установки, официальный сценарий установки и обновления, состояние, подключение/отключение, очистка кэша и пользовательских данных, отдельное управление автозапуском CLI и графической оболочки.
- Динамическое обнаружение сетевых интерфейсов и настройка исходящего интерфейса AdGuard VPN CLI. Список устройств определяется во время работы; имена личных профилей NetworkManager не зашиты в код. Сам CLI поддерживает выбор одного исходящего интерфейса.
- Вкладка исключений сайтов, использующая штатные списки AdGuard VPN CLI в режимах General и Selective.
- Экспериментальное раздельное туннелирование приложений через TUN в двух режимах: только выбранные приложения через VPN либо все приложения через VPN, кроме выбранных. Используются отдельные ярлыки, пользовательские systemd-scope, cgroup v2, nftables и отдельные правила маршрутизации IPv4/IPv6. Flatpak-приложения обнаруживаются и запускаются через flatpak run в scope, но фактическую маршрутизацию Flatpak sandbox/DBus необходимо подтвердить на целевой системе.
- Интерактивная справка, открываемая в браузере, с явным указанием на независимый статус проекта.
- Вкладка DNS в намеренно ограниченном тестовом режиме.

## Раздельное туннелирование

### Сайты

Вкладка «Исключения сайтов» управляет штатной функцией CLI:
- **General** — перечисленные сайты идут напрямую, вне VPN.
- **Selective** — через VPN идут только перечисленные сайты.

Используется один список доменов и один активный режим; переключение режима меняет трактовку этого списка. Управление списком не переключает режим автоматически. Список сайтов независим от выбора приложений. Официальная документация: [Настройки AdGuard VPN для Linux](https://adguard-vpn.com/kb/ru/adguard-vpn-for-linux/settings/).

### Приложения

Маршрутизация приложений реализована через документированный режим AdGuard VPN CLI `SCRIPT` и TUN. В режиме **«Только выбранные приложения через VPN»** через туннель направляются только приложения, запущенные из созданных ярлыков в отдельной пользовательской systemd slice; остальные процессы используют обычную системную маршрутизацию. В режиме **«Все приложения через VPN, кроме выбранных»** трафик пользовательской systemd-сессии помечается для VPN, а выбранные приложения из специальных ярлыков получают метку обхода VPN и используют основную таблицу маршрутов. Для помеченного трафика создаются отдельная таблица маршрутов и правила IPv4/IPv6; основной маршрут по умолчанию не заменяется. Частные, link-local, CGNAT и multicast-адреса остаются в основной таблице для доступа к локальной сети. Перед настройкой сохраняются прежние режим VPN, режим маршрутизации и route script. Кнопка отключения удаляет только созданные проектом правила и восстанавливает сохранённые настройки. Фоновый наблюдатель также удаляет их при исчезновении TUN-интерфейса: текущий API route script CLI не предоставляет отдельный callback отключения. Перед применением или отключением разорвите VPN-соединение; после применения подключитесь снова.

**Ограничения и статус испытаний:** уже работающие приложения нужно закрыть и запустить через новые ярлыки. Flatpak теперь обнаруживается и запускается через `flatpak run` в созданной scope; прохождение трафика через TUN для Flatpak sandbox/DBus ещё не подтверждено. Snap, raw/ICMP-трафик, отдельные sandbox-сценарии и DNS-резолверы, отличные от `systemd-resolved`, не проверены. DNS не разделяется по приложениям: запросы `systemd-resolved` направляются через VPN в обоих режимах, в том числе для приложений, чей остальной трафик идёт напрямую. Код покрыт автоматическими тестами и GitHub Actions, но ещё не прошёл интеграционную проверку на Debian 13/Cinnamon; до неё функция остаётся экспериментальной.

## DNS

Текущий менеджер DNS — тестовый механизм безопасности, ограниченный двумя явно разрешёнными тестовыми профилями. Он отказывается изменять активные тестовые профили и выполнять запись, если не подтверждено состояние AdGuard VPN TUN. Обычные пользовательские профили NetworkManager не изменяются. Это ещё не промышленная система управления DNS и не проверка утечек DNS.

## Сетевые интерфейсы

Вкладка динамически обнаруживает существующие нетуннельные интерфейсы, кроме loopback, и применяет документированную настройку `adguardvpn-cli config set-bound-if-override`. Профили NetworkManager не редактируются. Параметр CLI принимает один интерфейс; сброс выбора возвращает автоматический выбор интерфейса.

## Разработка и проверки

Активная ветка подготовки версии 0.2.0 — `release/0.2.0`; см. [черновой pull request №3](https://github.com/1919013/adguard-vpn-desktop/pull/3).

Локальные проверки:

```sh
python -m compileall -q core modules services ui main.py
python -m unittest discover -s tests -v
```

GitHub Actions выполняет эти проверки при отправке изменений и открытии pull request. Успешный CI не заменяет проверку работы на Debian/Cinnamon.

## Структура проекта

- `core/` — основная логика приложения.
- `modules/` — вкладки и контроллеры функций.
- `services/` — интеграция с системой и работа с состоянием.
- `ui/` — интерфейс GTK.
- `i18n/` — заготовки каталогов переводов; полноценное переключение RU/EN в интерфейсе ещё не реализовано.
- `tests/` — регрессионные тесты без GUI.

## Обновление текущей Git-копии

Для чистой копии репозитория с настроенной upstream-веткой:

```sh
git pull --ff-only
```

Для пользовательской установки, создаваемой графической оболочкой:

```sh
cd ~/.local/share/adguard-vpn-desktop/app && git pull --ff-only
```
