# ADGuard VPN Desktop

Открытая графическая оболочка GTK для **AdGuard VPN CLI** в Linux. Это сторонний общественный GUI-wrapper, а не официальное настольное приложение AdGuard; проект не связан с AdGuard.

## Что реализовано

- Подключение и отключение AdGuard VPN CLI, получение статуса и выбор VPN-локации.
- Обнаружение сетевых интерфейсов, IP-адресов и состояния устройств NetworkManager без изменения настроек.
- Каталог приложений Debian и Flatpak: поиск по префиксу без учёта регистра, добавление пользовательских исполняемых файлов и сохранение выбора.
- Кнопка «Запустить через VPN». Приложение запускается в отдельной systemd user scope, но сначала удерживается в состоянии ожидания. Запуск разрешается только после установки и независимой проверки правил маршрутизации.
- Ограниченный root-helper через pkexec и отдельное правило polkit.
- Два уровня наблюдения за VPN: GUI-supervisor и отдельная пользовательская systemd-служба watchdog. Watchdog не зависит от жизни графической оболочки и при отключении VPN или смене TUN останавливает все защищённые systemd scope; общая политика сохраняется, пока не завершится последний процесс.
- Предварительная проверка DNS: активный /etc/resolv.conf должен точно совпадать с DNS-файлом AdGuard VPN CLI, а маршруты к DNS-серверам должны проходить через активный TUN.
- Правила nftables помечают сокеты выбранного приложения и DNS-пакеты к проверенным DNS-серверам CLI. Трафик приложения и эти DNS-запросы блокируются, если выходной интерфейс не является активным TUN.
- Добавлены Debian-метаданные пакета и сборка пакета в GitHub Actions.

## Важные ограничения

- Для нескольких приложений используется общая `app-adguard-vpn.slice`: каждое приложение запускается в собственном systemd scope внутри неё, а одна nftables/ip rule политика применяется к родительской cgroup. Повторный запуск проверяет и переиспользует уже установленную политику. Удаление правил откладывается, пока в общей cgroup остаётся хотя бы один защищённый процесс. Это снимает прежнее ограничение на один процесс на уровне архитектуры, но одновременная работа Chrome и Telegram ещё должна пройти автоматические и реальные испытания Debian 13.
- Приложения с D-Bus activation и уже работающие экземпляры не запускаются через этот механизм: иначе запрос мог бы попасть в процесс вне защищённой cgroup.
- Локальные DNS-stub резолверы, например systemd-resolved/dnsmasq, пока отклоняются, пока не будет безопасно проверена их upstream-конфигурация.
- GUI-supervisor и независимая пользовательская systemd-служба периодически проверяют CLI. Watchdog останавливает только scope с префиксом `adguard-vpn-`, не затрагивая прочие приложения. После остановки он просит фиксированный polkit-helper очистить принадлежащие проекту правила; если очистка не подтверждена, правила остаются в ядре как fail-closed защита.
- Проверка DNS намеренно строгая. Если системный DNS не использует адреса из файла AdGuard VPN CLI и не маршрутизируется через TUN, запуск приложения запрещается.
- Сборка пакета и автоматические тесты проверяются в GitHub Actions, но установка, реальная работа watchdog, polkit, nftables и маршрутизации на Debian 13 ещё не проводились. Раздельное туннелирование нельзя считать готовым для повседневного использования до этих испытаний.
- Вкладка DNS по-прежнему ограничена явно разрешёнными тестовыми профилями; универсального управления DNS NetworkManager пока нет.
- Применение выбранных сетевых интерфейсов, полное управление продуктом AdGuard и справка в браузере ещё не завершены.

## Ограничение AdGuard VPN CLI

В AdGuard VPN CLI есть режимы TUN/SOCKS, режимы маршрутизации туннеля (AUTO, SCRIPT, NONE) и исключения доменов через site-exclusions. Исключения доменов не являются списком приложений или процессов. Поэтому механизм раздельной маршрутизации процессов в этом проекте реализуется отдельно, поверх CLI.

См. [документацию AdGuard VPN для Linux по настройкам](https://adguard-vpn.com/kb/adguard-vpn-for-linux/settings/) и [исключениям](https://adguard-vpn.com/kb/adguard-vpn-for-linux/exclusions/).

## Архитектура

- core/ — взаимодействие с CLI и основная логика.
- modules/ — пользовательские функции.
- services/ — интеграция с операционной системой.
- ui/ — интерфейс GTK.
- i18n/ — переводы.
- docs/ — документация.
- tests/ — автоматические тесты.

Интерфейс не запускает привилегированные системные команды напрямую. Такие операции ограничены фиксированным helper и проверенными аргументами.

## Безопасность

- Обнаружение интерфейсов и предварительная проверка DNS работают только на чтение.
- DNS firewall-защита действует во время защищённого запуска и ограничена проверенными адресами DNS-резолверов.
- Существующие таблицы nftables не перезаписываются и не присваиваются проекту.
- Состояние принадлежащих проекту правил хранится с ограниченными правами и удаляется после завершения защищённого приложения.
- Не добавлять в Git учётные данные, ключи и локальные DNS-снимки.
